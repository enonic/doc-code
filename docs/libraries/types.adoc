The shared types that flow across the Enonic libraries

== Introduction

This page is the canonical reference for the cross-library types. 

principals, binary streams, the content object, page components, and more. They are defined once in the `@enonic-types/core` package and re-exported by the individual `@enonic-types/lib-*` packages, so the same `User`, `Content`, or `ByteSource` you receive from one library is the exact type another library accepts.

Library pages name them and link here rather than redefining them. For how to install and wire the type packages, see <<../tooling/typescript#, TypeScript>>.

NOTE: These are the TypeScript shapes of the runtime objects. The conceptual models behind them — the content model, the query language, form schemas — are documented in the https://developer.enonic.com/docs/cms[CMS] and https://developer.enonic.com/docs/platform[XP platform] docs, linked from the relevant types below.

== Principals and keys

Principal keys are branded string templates — a `User` key always reads `+user:<idprovider>:<id>+`, a group key `+group:<idprovider>:<id>+`, and a role key `+role:<id>+`.

[#principal-key]
=== PrincipalKey

A union of the three key kinds: `UserKey | GroupKey | RoleKey`.

[#user-key]
=== UserKey

Template string `+user:${string}:${string}+` — e.g. `user:system:alice`.

[#group-key]
=== GroupKey

Template string `+group:${string}:${string}+` — e.g. `group:system:editors`.

[#role-key]
=== RoleKey

Template string `+role:${string}+` — e.g. `role:system.admin`.

[#principal-type]
=== PrincipalType

One of `'user'`, `'group'`, or `'role'`.

[#principal]
=== Principal

A union of the three principal objects: `<<user, User>> | <<group, Group>> | <<role, Role>>`. Use the `type` discriminant to tell them apart.

== Binary and resources

[#byte-source]
=== ByteSource

An opaque handle to a binary stream. You don't read its fields directly — you pass it to library functions (for example `+io.readText+`, `+io.getSize+`, attachment and media APIs) that consume or produce binary data. Obtain one from `<<lib-io#, lib-io>>` (`newStream`, a resource stream) or from content attachments.

[#resource]
=== Resource

A handle to an application resource on the classpath, returned by `+io.getResource+`.

[.lead]
Methods

[%header,cols="1%,1%,98%a"]
[frame="none"]
[grid="none"]
|===
| Name | Type | Description
| exists() | boolean | Whether the resource exists.
| getSize() | number | Size in bytes.
| getTimestamp() | number | *Deprecated.* Last-modified time, in milliseconds since the epoch. Not a dependable measure of when the resource last changed: for a resource in an application bundle the value comes from its jar entry, which build tools normalize to a constant for reproducible builds (Gradle does so by default as of version 9) — so it reflects the build, not the file. Only a resource backed by a repository node carries a genuine modification time; for file-backed resources the value is meaningful in development mode only.
| getStream() | <<byte-source, ByteSource>> | The resource's binary stream.
|===

[#resource-key]
=== ResourceKey

Identifies an application resource by application key and path.

[.lead]
Methods

[%header,cols="1%,1%,98%a"]
[frame="none"]
[grid="none"]
|===
| Name | Type | Description
| getApplicationKey() | string | The owning application key.
| getPath() | string | Resource path within the application.
| getUri() | string | Full resource URI.
| getName() | string | Resource name.
| getExtension() | string | File extension.

== Page and components

A content's `page` (and a fragment's `fragment`) is a tree of components. Every component carries a `type` discriminant — one of `'page'`, `'layout'`, `'part'`, `'text'`, or `'fragment'`. There is no separate `Page` type: the page-level node is a <<page-component, PageComponent>>. The same tree is what <<../libraries/lib-content#pages-and-components, lib-content>> takes when creating or updating a page; `path` and a region's `name` are set by XP when the page is stored and are ignored on input.

[#component]
=== Component

A union of the five component kinds, discriminated by `type`:
`<<page-component, PageComponent>> | <<layout-component, LayoutComponent>> | <<part-component, PartComponent>> | <<text-component, TextComponent>> | <<fragment-component, FragmentComponent>>`.

== Repository nodes

[#node]
=== Node

A stored repository node, as returned by the `lib-node` connection methods (`create`, `get`, `modify`, `move`, …). A node is its system properties merged with the caller's own data: every non-underscore property is application data, and the underscore-prefixed system properties are:

[%header,cols="1%,1%,98%a"]
[frame="none"]
[grid="none"]
|===
| Name | Type | Description
| `+_id+` | string | Generated, unique node id.
| `+_name+` | string | Node name, unique among its siblings.
| `+_path+` | string | Full path to the node.
| `+_childOrder+` | string | Child order expression (for example, `+_ts DESC+`).
| `+_manualOrderValue+` | number | *Optional.* Numeric value used when siblings are ordered manually.
| `+_nodeType+` | string | Node type; `data` for ordinary nodes.
| `+_permissions+` | object[] | Access-control entries (`principal`, `allow`, `deny`) for the node.
| `+_indexConfig+` | object | Index configuration controlling how the node's data is indexed.
| `+_ts+` | string | Timestamp of the node's current version, as an ISO-8601 instant.
| `+_versionKey+` | string | Key of the node's current version.
|===

All other properties are the node's own data. See the https://developer.enonic.com/docs/platform[XP platform node API] for the full model.

== HTTP

[#request]
=== Request

The object passed to an HTTP function (`GET`, `POST`, filters, error handlers). Its fields — `method`, `path`, `params`, `headers`, `cookies`, `body`, and the rest — are documented in depth in <<../web#, Web>>, the canonical home for the request/response model.

[#response]
=== Response

The object an HTTP function returns — `status`, `body`, `contentType`, `headers`, `cookies`, `pageContributions`, `redirect`, and more. All fields are optional. See <<../web#, Web>> for the full model and examples.

[#request-access-token]
=== RequestAccessToken

image:xp-820.svg[XP 8.2.0,opts=inline] The access token the request was authenticated with: one XP issued, or one of another issuer that the ID provider verified and passed to <<lib-auth#login, `login({accessToken})`>>. Present as `request.accessToken`. See <<../web/request-response#access-token, token-authenticated requests>>.

[.lead]
Properties

[%header,cols="1%,1%,98%a"]
[frame="none"]
[grid="none"]
|===
| Name | Type | Description
| issuer | string | Who issued the token: XP's issuer name (`token.issuer` in `com.enonic.xp.security.cfg`), or the upstream issuer of a promoted token.
| clientId | string | The client id the token was issued to, as the client gave it; `null` when a promoted token has none. Not a verified identity.
| grantId | string | The grant the token was issued under, stable across refreshes; `null` for a promoted token.
| scope | string[] | The scopes the request was granted, sorted: the grant's current scopes for an XP token, the token's own for a promoted one. The roles they imply are already applied to the logged-in user.
| audience | string[] | The audiences the token is for, sorted.
|===

== Other

[#script-value]
=== ScriptValue

A lazy wrapper around a value crossing the Java/JavaScript boundary — used by APIs that accept arbitrary caller data (for example audit-log data, task config). Rather than fields, it exposes inspection methods: `isArray()`, `isObject()`, `isValue()`, `isFunction()`, `getValue()`, `getKeys()`, `hasMember(key)`, `getMember(key)`, `getArray()`, `getMap()`, `getList()`.

== Query and form types

[#form-item]
=== FormItem

A single item in a content type, mixin, or form-fragment schema. `FormItem` is a union discriminated by `formItemType`, with five kinds:

[%header,cols="1%,99%a"]
[frame="none"]
[grid="none"]
|===
| formItemType | Description
| `Input` | A data-entry field. Properties: `name`, `label`, `inputType` (names the editor — `TextLine`, `HtmlArea`, `ContentSelector`, …), `occurrences` (`+{ minimum, maximum }+`), `helpText`, `validationRegexp`, `default`, `config`.
| `ItemSet` | A repeatable group of nested `items` (`FormItem[]`). Properties: `name`, `label`, `occurrences`, `items`, plus `helpText`.
| `Layout` | A visual grouping that carries no data of its own. Properties: `name`, `label`, `items` (`FormItem[]`).
| `OptionSet` | A set of selectable `options`, each with its own nested `items`. Properties: `name`, `label`, `occurrences`, `selection` (`+{ minimum, maximum }+`), `options`, `helpText`, `expanded`.
| `FormFragment` | A reference to a reusable form fragment. Property: `name`.
|===

Every kind has a `name` and a `label`. For the full per-`inputType` configuration, see the https://developer.enonic.com/docs/cms[CMS schema docs].

[#query-dsl]
=== Query DSL types

`QueryDsl`, `SortDsl`, `Filter`, `Aggregations`, and `Highlight` model the query DSL. They are documented with the storage layer rather than duplicated here — see the https://developer.enonic.com/docs/platform/stable/storage[XP storage and querying docs] and <<../storage/querying#, Querying>>.
