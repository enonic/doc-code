The Enonic Development Kit (EDK) is the combined server-side TypeScript framework and tools that for Enonic app development.

== Audience

Looking to customize Enonic XP, you've come to the right place. 

Code in TypeScript, build and deploy your <<fundamentals/apps#, Enonic app>> with full access to XP's persistence, clustering, identity, scheduling, and HTTP machinery — powered by the <<fundamentals/runtime#, XP runtime>>, without Node.js, without a separate JS process, and with cluster-aware semantics out of the box.

This documentation covers the app-development surface only, other relevant documentation includes:

* https://developer.enonic.com/docs/cms[CMS docs] for content modelling and content APIs
* https://developer.enonic.com/docs/content-studio[Content Studio docs] for the content authoring interface
* https://developer.enonic.com/docs/xp[XP platform docs] for platform features and architecture

== Introduction

XP is highly modular: a single instance hosts many apps side by side. Each app is a self-contained bundle that can contribute <<schemas#, content schemas>>, custom <<web/apis#, APIs>>, <<web/tools#, admin tools>> and <<web/extensions#, extensions>>, <<web/id-providers#, ID providers>>, <<web/webapps#, webapps>>, or full <<web/sites#, websites>> — all powered by the same JS/TS runtime and the same standard <<libraries#, libraries>>.

== Where to start

<<tooling#, Tooling>>:: The CLI, sandboxes, starters, build system, and CI/CD setup that get you building quickly.

<<fundamentals#, Fundamentals>>:: The runtime, the app model, the module system, lifecycle hooks, and the cluster-wide event bus.

<<web#, Web>>:: The shared request pipeline, primitives (request/response, filters, error handlers, websockets, SSE), ID providers, and the four services XP dispatches to.

<<web/apis#, APIs>>, <<web/tools#, Admin Tools>> and <<web/extensions#, Extensions>>, <<web/sites#, Sites>>, <<web/webapps#, Webapps>>:: The four services exposed by XP — custom APIs, admin UIs and extensions, CMS-driven sites, and standalone web applications.

<<background#, Background>>:: Tasks and scheduled jobs for asynchronous work.

<<libraries#, Libraries>>:: The platform's standard libraries — content, repos, identity, mail, and more.
