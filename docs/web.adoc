= Developing for the web
:toc: right
:imagesdir: web/images

Every client interaction with Enonic XP — browser request, API call, admin tool, websocket upgrade etc flow through a common http gateway in XP, aka the Web endpoint.

== Services

The Web endpoint listens on `port 8080` (configurable) and dispatches requests to one of four *services*, each with a fixed URL prefix and a distinct role:

[cols="1,3", options="header"]
|===
| Service | Purpose
| <<web/apis#, /api>> | Custom HTTP APIs, microservices, headless integrations.
| <<web/tools#, /admin>> | XP administration UIs (Content Studio is itself an admin tool) and extensions that mount inside them.
| <<web/sites#, /site>> | CMS-driven websites: pages, parts, layouts, content rendering.
| <<web/webapps#, /webapp>> | Standalone web applications — served by your app, no CMS context.
|===

== ID providers
<<web/id-providers#, ID providers>> work across the services to provide pluggable authentication and that hooks into the request pipeline — `handle401`, `autoLogin`, `login`/`logout` endpoints, and ID-provider-as-HTTP-function.

A single application can contribute to any number of these simultaneously — a custom API, an admin extension and a website, all in the same app, all sharing the same code and libraries.

== Request flow

Every request, regardless of which service ultimately handles it, passes through a common pre-processing pipeline before reaching your code:

image::common-pipeline.svg[Common HTTP request pipeline, 768px]

Vhost filters:: Request routing based on <<deployment/vhosts#, virtual hosts>>.

Platform filters:: Optional system level request filters.

Autologin filter:: The <<deployment/vhosts#, virtual host contextual ID provider>> is invoked, unless a user already exists in the context.

Service pipeline:: The pipeline of the matching service is executed (API invocation, admin tool routing, site rendering, or webapp dispatch).

Auth handler:: Triggered if the pipeline returns a `401 Unauthorized`. The contextual <<web/id-providers#, ID provider>> is invoked and may handle the request.

Error handler:: If the pipeline returns an unhandled error (everything but `200 OK`) that was not handled by an ID provider, the contextual <<web/error#, error handler>> kicks in.

Platform response filters:: Optional system level response filters.

Standard error handler:: Finally, if the request fails with an error that is still unhandled, XP's standard error handler kicks in.
